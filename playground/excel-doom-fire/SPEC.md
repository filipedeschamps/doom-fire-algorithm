# excel-doom-fire — vanilla (M1) SPEC

Doom fire in plain Excel: formulas + conditional formatting, no macros.
Upstream provenance root: `playground/1st-implementation-with-tables/fire.js @854c39f`
(full 854c39ff00f6f4688a674a4086d3c9f7c02497e1), cited as `fire.js Lx-y`.

Testing: no GUI Excel. Structure via openpyxl; values via LibreOffice headless
recalculation (`tests/support/recalc.py`). Verify:
`cd playground/excel-doom-fire && uv run --python 3.11 --with-requirements tests/requirements.txt pytest tests/acceptance/vanilla -q`

Conventions: coordinates are 1-based Excel A1. Fire grid = `Fire!A1:BH40`
(60 columns A..BH, 40 rows). Row 40 is the bottom (source) row.

## Decisions

### D-01: Artifact
`vanilla/doom-fire.xlsx` (no macros, no `.xlsm`), generated by committed
`vanilla/build_vanilla.py` (openpyxl). The committed xlsx is the deliverable;
regenerating must give an equivalent workbook (formulas, CF rules, dimensions).
Specs: [SPEC-001](#spec-001-macro-free-artifact), [SPEC-002](#spec-002-reproducible-generator)

### D-02: Grid and source
60 columns x 40 rows (fire.js L2-3). Bottom row equals single input cell `Source`
(default 36, valid 0..36). 36 = createFireSource, 0 = destroyFireSource (fire.js L82-98).
Specs: [SPEC-003](#spec-003-grid-and-source-cell), [SPEC-004](#spec-004-source-row)

### D-03: Compatibility and decay sheet
No LET, dynamic arrays, LAMBDA, circular refs or iterative calc; works in Excel 2010+
and LibreOffice. Per-pixel decay lives on separate sheet `Decay` (`RANDBETWEEN(0,2)`
per cell, fire.js L43); the sheet may be hidden.
Specs: [SPEC-005](#spec-005-decay-sheet), [SPEC-006](#spec-006-compatibility)

### D-04: Propagation (pull form of fire.js L35-49)
`fire[r][c] = MAX(0, fire[r+1][c+d] - d)` with `d = decay[r][c]`; when `c+d` is beyond
the last column the pulled value is 0. Exact, deterministic invariant over the
recalculated cached values of both sheets.
Specs: [SPEC-007](#spec-007-propagation-invariant)

### D-05: Animation
Every recalc is one frame (RAND is volatile). Hold F9 to animate. README says so.
Specs: [SPEC-008](#spec-008-volatile-frames), [SPEC-009](#spec-009-readme-explains-animation)

### D-06: Rendering
37 conditional-format rules, one per intensity 0..36, each filling with the exact RGB
from fire.js L5. Number format hides the digits. Cells square-ish, gridlines off on
the fire sheet.
Specs: [SPEC-010](#spec-010-palette-conditional-formats), [SPEC-011](#spec-011-cell-appearance)

### D-07: Upstream conventions
Everything lives in `playground/excel-doom-fire/`; one line is added to the top-level
README.md experiments list in the existing format. (From the card's repo conventions,
not the orchestrator's design set.)
Specs: [SPEC-012](#spec-012-top-level-readme-entry)

## SPEC-001: Macro-free artifact
[D-01](#d-01-artifact) · [P: none — packaging; whole-program port of fire.js L1-130]
`vanilla/doom-fire.xlsx` exists, is a valid OOXML zip, contains no vbaProject part and
no macroEnabled content type, and `vanilla/` holds no `.xlsm`.
Tests: test_spec001_*

## SPEC-002: Reproducible generator
[D-01](#d-01-artifact) · [P: none — packaging]
`python vanilla/build_vanilla.py --out PATH` exits 0 and writes a workbook equivalent
to the committed xlsx: same defined names, sheet names, per-sheet dimensions, sheet
state, every cell's formula/value, and every CF rule (range, type, operator, formula,
fill colours).
Tests: test_spec002_*

## SPEC-003: Grid and source cell
[D-02](#d-02-grid-and-source) · [P: fire.js L2-3, L82-98]
Sheets `Fire` (first) and `Decay` exist. Every cell of `Fire!A1:BH40` is a formula.
Defined name `Source` resolves to exactly one cell on `Fire`, outside A1:BH40, holding
36 by default, with whole-number data validation between 0 and 36. `Decay!A1:BH39` is
fully populated and row 40 of `Decay` is empty.
Tests: test_spec003_*, test_guard_upstream_constants_pinned

## SPEC-004: Source row
[D-02](#d-02-grid-and-source) · [P: fire.js L82-98]
Every cell of `Fire!A40:BH40` is the formula `=Source`. After recalculation row 40
equals `Source` in every column (tested 36, 17, 0). `Source`=0 yields an all-zero grid
(destroy); `Source`=36 yields a lit fire (row 39 max >= 34).
Tests: test_spec004_*

## SPEC-005: Decay sheet
[D-03](#d-03-compatibility-and-decay-sheet) · [P: fire.js L43]
Every cell of `Decay!A1:BH39` is exactly `=RANDBETWEEN(0,2)`. After recalculation the
values are integers in {0,1,2}, and all three occur.
Tests: test_spec005_*

## SPEC-006: Compatibility
[D-03](#d-03-compatibility-and-decay-sheet) · [P: none — Excel 2010+ target]
No formula uses LET, LAMBDA, dynamic-array/new-generation functions (list in test),
`_xlfn`/`_xlws` prefixes, spill `#`, array or data-table formulas; no external links;
workbook calc `iterate` is off; recalculation yields no error values in `Fire` or
`Decay` (thus no circularity).
Tests: test_spec006_*

## SPEC-007: Propagation invariant
[D-04](#d-04-propagation-pull-form-of-firejs-l35-49) · [P: fire.js L35-49]
In every recalculation, for each r in 1..39 and c in 1..60, with `d = Decay[r][c]`:
`Fire[r][c] = MAX(0, Fire[r+1][c+d] - d)`, or 0 when `c+d > 60`. Rows 1..39 of `Fire`
reference the `Decay` sheet. All Fire values are integers in 0..36. Holds for Source
36 (three independent recalcs), 18 and 0.
Tests: test_spec007_*, test_guard_invariant_checker_detects_errors, test_guard_libreoffice_recalc_harness

## SPEC-008: Volatile frames
[D-05](#d-05-animation) · [P: fire.js L12 — 50 ms frame interval ≙ one recalc per frame]
Two independent recalculations of the same workbook differ in both `Decay` and `Fire`
(Source 36): each recalc is a new frame.
Tests: test_spec008_*, test_guard_libreoffice_recalc_harness

## SPEC-009: README explains animation
[D-05](#d-05-animation) · [P: fire.js L12]
`playground/excel-doom-fire/README.md` exists and says to hold F9, and that each
recalculation is one frame.
Tests: test_spec009_*

## SPEC-010: Palette conditional formats
[D-06](#d-06-rendering) · [P: fire.js L5]
`Fire` has exactly 37 conditional-format rules, each `cellIs`/`equal` with a single
integer operand k (each of 0..36 once), filling with the exact RGB of upstream palette
entry k (parsed from fire.js L5 in the checkout), and together covering all of
`A1:BH40`.
Tests: test_spec010_*, test_guard_upstream_constants_pinned

## SPEC-011: Cell appearance
[D-06](#d-06-rendering) · [P: fire.js L132+ table render, cellpadding=0]
Every cell in `Fire!A1:BH40` has number format `;;;`; `Fire` gridlines are off; column
widths and row heights are explicit and uniform, with width/height pixel ratio within
0.8..1.25 (px ≈ chars·7+5 wide; pt·96/72 tall).
Tests: test_spec011_*

## Out of scope

write-shift form of propagation (the pull form of D-04 is specified instead).
